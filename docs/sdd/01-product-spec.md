# SDD-01｜CRM Agent 产品验证规格

## 目标

验证医药代表能否在统一 Agent 工作台完成客户洞察、访前准备、材料推荐、机构准入、访后记录与跟进闭环；所有高风险医学建议必须可溯源，所有写操作必须经人工确认。

## 用户与任务

| 角色 | 任务 | 成功输出 | 不可逾越边界 |
| --- | --- | --- | --- |
| MR | 访前准备 | 客户事实、拜访重点、已批准资料、开场建议 | 不引用失效/未审批资料 |
| MR | 访后记录 | 医生反馈、观念变化、下次拜访、待办草稿 | 不自动写回 CRM |
| MR | 奖金试算 | 金额、政策版本、计算明细 | LLM 不得自行计算金额 |

## MVP 验收

1. `/api/agent` 根据 `pre` / `post` 路由至对应任务链，并返回逐节点轨迹。
2. 访前输出至少一份已批准证据及版本信息；机构问题改走经营工具，不伪造医学引用。
3. 访后从自然语言中抽取结构化字段，生成待办草稿；未携带确认令牌不得写回。
4. 奖金结果仅由规则服务生成，并返回匹配的政策版本。
5. 超适应症问题被拦截、不给出医学结论。
6. 工作台必须展示每次任务的路由、Skill 版本、工具轨迹和可展开来源；会话按医生绑定并持久化，访前准备、面对面手卡与访后确认写入同一条时间线。
7. 外部模型可参与意图分类、访后抽取及基于工具结果的表达；事实与引用仍来自工具。无 Key 时使用规则模式。
